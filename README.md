# Clicker · Weather · Dog Breeds

Тестовое задание (Unity): три вкладки с нижней навигацией — кликер, погода и список пород собак. Все запросы к серверу выполняются через общую очередь.

Проект написан по принципам **чистой архитектуры (Clean Architecture)**: бизнес-логика не зависит от Unity, UI и сети, а слои связаны через интерфейсы. Взаимодействие с UI построено на MVC и MVP: ввод идёт снаружи внутрь через контроллеры (MVC), а отображение — изнутри наружу через презентеры (MVP).

## Запуск

- Unity **6000.3.21f1** (URP 2D). Подходит любая версия 2022.3+.
- Откройте сцену `Assets/_Project/Scenes/SampleScene.unity` и нажмите Play.

## Стек

Zenject, UnityWebRequest, UniRx, UniTask, DOTween, TextMeshPro.

## Что реализовано

### Кликер
- Тап по кнопке начисляет валюту; каждые 3 секунды кнопка «нажимается» сама (автосбор).
- Энергия: старт и максимум 1000, тап и автосбор стоят по 1, регенерация +10 каждые 10 секунд.
- Отклик на тап и автосбор: частицы, попап с наградой, который летит к счётчику валюты, анимация кнопки и звук.
- Все числа (стоимость, награды, интервалы, максимум) настраиваются в ScriptableObject `ClickerConfig`.

### Погода
- Источник: `https://api.weather.gov/gridpoints/TOP/32,81/forecast`.
- Пока открыта вкладка, каждые 5 секунд в очередь встаёт запрос. При уходе с вкладки выполняющийся запрос отменяется, а ожидающий убирается из очереди.
- Показывается иконка и температура. Иконка загружается отдельным запросом и кэшируется, данные попадают в сущность только после её загрузки.

### Породы собак
- Источник: `https://dogapi.dog/api/v2/breeds`.
- При входе на вкладку встаёт запрос списка, пока он идёт, показан загрузчик. Показывается 10 пород в формате `1 - name`.
- По клику встаёт запрос по id породы, на карточке виден загрузчик, затем открывается один общий попап с названием и описанием (высота подстраивается под текст).
- Клик по другой породе отменяет предыдущий запрос (или убирает из очереди) и запускает новый. Уход с вкладки отменяет всё.

## Архитектура

Чистая архитектура с MVC и MVP. Главное правило — **зависимости направлены внутрь**: `Entities` не знают ни о ком, `UseCases` зависят только от сущностей и интерфейсов (портов), `InterfaceAdapters` и `Infrastructure` реализуют эти порты и подключаются через Zenject. Каждая фича разделена на слои:

```
Feature/Scripts
├── Entities           состояние и правила (без Unity-зависимостей)
├── UseCases           сценарии; зависят только от портов (интерфейсов)
├── InterfaceAdapters  контроллеры и презентеры, порты вью
├── Infrastructure     MonoBehaviour-вью, фабрики, запросы
└── Installer          Zenject-привязки
```

Поток данных идёт по кругу:

- **Снаружи внутрь (MVC):** вью → контроллер → use case → сущность. Контроллер принимает действия пользователя и вызывает сценарий.
- **Изнутри наружу (MVP):** сущность → презентер → вью. Презентер подписывается на изменения сущностей и обновляет экран через интерфейс вью.

Use case не знает про Unity: звук, анимация и показ попапа вызываются через порты.

| Папка | Что внутри |
|---|---|
| `Core` | `ObjectPool`, `GrowingPool`, интерфейсы пула, `ITabState` |
| `Network` | очередь запросов и исполнитель на `UnityWebRequest` |
| `Features/Tabs` | переключение вкладок (`TabsStateMachine`, состояния вкладок) |
| `Features/Clicker` | кликер, энергия, кошелёк, автосбор, VFX и звук |
| `Features/Weather` | запрос погоды, таймер обновления, хранилище иконок |
| `Features/Breeds` | список пород, карточки (пул), попап описания |

## Заметки

- Таймеры кликера (автосбор и регенерация энергии) идут только пока открыта его вкладка: `Tick` получает активное состояние.
